TC-IF-001: Murabaha Markup Calculation

PreconditionsIslamicFinanceCalculationService is instantiated. Asset cost = 100,000 AED, markup rate = 15%.
Steps
  1. Call calculateMurabaha(100000, 15.0, 36) with a 36-month term.
  2. Verify the returned total price.
  3. Verify the monthly installment amount.
Expected ResultTotal price = 115,000 AED. Profit amount = 15,000 AED. Monthly installment = 115,000 / 36 = 3,194.44 AED (rounded to 2 decimal places). No field references "interest".

TC-IF-002: Diminishing Musharaka Equity Reduction Over Time

PreconditionsProperty value = 1,000,000 AED. Bank equity = 80%, customer equity = 20%. Term = 20 years. Monthly buyout.
Steps
  1. Call calculateMusharaka(1000000, 80.0, 240).
  2. Verify equity split after 1 payment.
  3. Verify equity split after 120 payments (midpoint).
  4. Verify equity split after 240 payments (completion).
Expected ResultAfter 1 payment: bank equity decreases by 1/240 of original 80%. After 120 payments: bank equity = 40%, customer = 60%. After 240 payments: bank equity = 0%, customer = 100%.

TC-IF-003: Ijara Rental Schedule Generation

PreconditionsAsset value = 500,000 AED. Lease term = 60 months. Annual rental rate = 6%.
Steps
  1. Call calculateIjara(500000, 6.0, 60).
  2. Verify the rental schedule has 60 entries.
  3. Verify each monthly rental amount.
Expected Result60 monthly rental payments generated. Monthly rental = (500,000 * 6%) / 12 = 2,500 AED. Total rental over term = 150,000 AED.

TC-IF-004: Mudarabah Profit Split by Agreed Ratio

PreconditionsInvestment amount = 200,000 AED. Profit = 30,000 AED. Agreed ratio: customer 60%, bank 40%.
Steps
  1. Call calculateMudarabahProfit(30000, 60.0).
  2. Verify customer share and bank share.
Expected ResultCustomer profit = 18,000 AED (60%). Bank profit = 12,000 AED (40%). Total = 30,000 AED.

TC-IF-005: Riba Transaction Rejection

PreconditionsAn Islamic loan product (type = MURABAHA) exists.
Steps
  1. Attempt to apply conventional interest calculation method (COMPOUND_MONTHLY) to the Islamic loan.
Expected ResultSystem throws ShariahViolationException with message indicating interest-based calculations are prohibited for Islamic products.

  1. Create a Wadiah current account for the customer.
  2. Verify account properties.

TC-IF-007: Islamic Loan Application E2E with SSB Approval

PreconditionsCustomer is KYC-verified. Murabaha product type configured. SSB reviewer exists.

  2. Verify application status is PENDING_SSB_APPROVAL.

  5. Verify audit trail contains SSB approval event.
Expected ResultLoan application moves through SSB approval workflow. Final status = APPROVED. Audit trail records submitter, reviewer, decision, and timestamp.

TC-IF-008: Profit Distribution to Mudarabah Savings Account

TC-RC-001: Zakat Calculation Above Nisab Threshold

PreconditionsEligible assets = 500,000 AED. Nisab threshold = 20,000 AED (configurable, based on gold price).
Steps
  1. Call calculateZakat(500000, 20000).
  2. Verify Zakat amount.
Expected ResultZakat = 500,000 * 2.5% = 12,500 AED.

TC-RC-002: Zakat Below Nisab — Returns Zero

PreconditionsEligible assets = 15,000 AED. Nisab threshold = 20,000 AED.
Steps
  1. Call calculateZakat(15000, 20000).
  2. Verify Zakat amount.
Expected ResultZakat = 0 AED (assets below nisab threshold).

TC-RC-003: Zakat Excludes Non-Zakatable Assets

PreconditionsTotal assets = 600,000 AED. Non-zakatable assets (primary residence, personal vehicle) = 400,000 AED. Nisab = 20,000 AED.
Steps
  1. Call calculateZakat(600000, 400000, 20000) with non-zakatable exclusion.
  2. Verify eligible amount and Zakat.
Expected ResultEligible assets = 200,000 AED. Zakat = 200,000 * 2.5% = 5,000 AED.

TC-RC-004: goAML Report XML Schema Validation

PreconditionsA suspicious transaction with amount = 50,000 AED, customer ID, and transaction details.
Steps
  1. Generate goAML report for the suspicious transaction.
  2. Validate output against CBUAE goAML XML schema.
  3. Verify all mandatory elements are present.
Expected ResultXML output passes schema validation. Contains: reporting entity, subject details, transaction amounts, suspicion indicators, and report metadata.

TC-RC-005: CBUAE Prudential Return Generation

PreconditionsBank financial data available: total assets, risk-weighted assets, capital, liabilities.
Steps
  1. Generate CBUAE prudential return report.
  2. Verify capital adequacy ratio calculation.
  3. Verify report format.
Expected ResultReport generated with correct capital adequacy ratio (Tier1 + Tier2 capital / risk-weighted assets). Format conforms to CBUAE requirements.

TC-RC-006: AML Threshold Uses AED 35,000

PreconditionsTransaction monitoring service configured for UAE jurisdiction.
Steps
  1. Process a transaction of 34,999 AED — verify no CTR triggered.
  2. Process a transaction of 35,000 AED — verify CTR triggered.
  3. Verify the threshold is not USD 10,000.
Expected ResultCTR triggered at AED 35,000. Transaction of 34,999 AED does not trigger CTR. The USD 10,000 BSA threshold is not used for UAE operations.

TC-RC-007: VAT Calculation on Banking Fees at 5%

PreconditionsBanking fee = 1,000 AED. VAT rate = 5%. Transaction is not VAT-exempt.
Steps
  1. Call calculateVat(1000, false).
  2. Verify VAT amount and total.
  3. Call calculateVat(1000, true) for an exempt transaction.
Expected ResultNon-exempt: VAT = 50 AED, total = 1,050 AED. Exempt: VAT = 0 AED, total = 1,000 AED.

TC-RC-008: End-to-End Regulatory Report Submission

PreconditionsSuspicious transaction flagged by monitoring. CBUAE reporting endpoint configured (mock).
Steps
  1. Monitoring flags transaction as suspicious.
  2. System generates goAML report.
  3. Report is validated and submitted to CBUAE endpoint.
  4. Verify submission status and audit trail.
Expected ResultReport generated, validated, and submitted successfully. Audit trail records generation time, validation result, submission time, and response status.

TC-MC-001: Multi-Currency Wallet Creation

PreconditionsCustomer with verified KYC. MultiCurrencyWalletService instantiated.
Steps
  1. Create wallets for AED, SAR, QAR, BHD, OMR, KWD.
  2. Verify each wallet is created with zero balance.
  3. Verify wallets are linked to the customer's primary account.
Expected Result6 currency wallets created. Each has currency code, zero balance, and a link to the parent account. All GCC currencies supported.

TC-MC-002: Currency Conversion With Spread

PreconditionsFX rate: AED/SAR mid-rate = 1.02. Spread = 0.5%.
Steps
  1. Convert 10,000 AED to SAR.
  2. Verify the applied rate includes spread.
  3. Verify the converted amount.
Expected ResultApplied rate = 1.02 * (1 - 0.005) = 1.0149 (sell rate). Converted amount = 10,000 * 1.0149 = 10,149 SAR. Spread revenue = 51 SAR equivalent.

TC-MC-003: CBUAE Reference Rate Lookup

PreconditionsFxRateService configured with mock CBUAE rate endpoint.
Steps
  1. Request rate for AED/USD.
  2. Verify rate is returned within cache TTL.
  3. Verify rate refresh after TTL expiry.
Expected ResultRate returned with timestamp. Cached for configured interval (15 min). Refreshed after expiry. Rate includes source = "CBUAE".

TC-MC-004: India Corridor Remittance Fee Calculation

PreconditionsRemittanceService instantiated. India corridor configured: flat fee = 15 AED, percentage = 0.25%, min fee = 15 AED.
Steps
  1. Calculate fee for remittance of 5,000 AED to India.
  2. Verify fee breakdown.
Expected ResultPercentage fee = 5,000 * 0.25% = 12.50 AED. Since 12.50 < 15, minimum fee applies. Total fee = 15 AED.

TC-MC-005: Remittance AML Limit Enforcement

PreconditionsIndia corridor AML limit = 100,000 AED per month. Customer has already remitted 95,000 AED this month.
Steps
  1. Attempt to remit 10,000 AED to India.
Expected ResultRemittance rejected or flagged for enhanced due diligence. Remaining monthly limit = 5,000 AED. Error indicates corridor limit exceeded.

TC-MC-006: Beneficiary Bank Validation

PreconditionsBeneficiary bank SWIFT code and country code available.
Steps
  1. Validate beneficiary with valid Indian bank SWIFT code (e.g., SBININBB).
  2. Validate with invalid SWIFT code.
Expected ResultValid SWIFT code passes validation with bank name resolved. Invalid SWIFT code returns validation error.

TC-MC-007: End-to-End Remittance to India Corridor

PreconditionsCustomer with KYC, funded AED wallet. India corridor configured. Mock correspondent bank.
Steps
  1. Submit remittance: 20,000 AED to India, beneficiary details provided.
  2. Verify AML checks pass.
  3. Verify FX conversion (AED to INR).
  4. Verify fee deduction.
  5. Verify transaction submitted to corridor.
Expected ResultRemittance processed end-to-end. AED deducted (amount + fee). INR amount credited to beneficiary. AML checks passed. Transaction record with corridor, FX rate, fees, and status.
